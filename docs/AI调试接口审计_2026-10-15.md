# AI 调试接口审计（2026-10-15）

审计版本：`9ab5996`，已从 `origin/main` 快进同步。此次远端新增“墨途远征”，经典章节冒险仍保留。

结论：远征已接入真实战斗和界面往返，但现有 JSON / 无头接口仍只驱动经典冒险。即便只检查单场战斗，也存在交互缺失、错误的自动目标和状态观察不足，目前不能把 AI 接口跑出的结果视为玩家实际体验的等价结果。

本轮完成同步、代码审查和定向复现；没有修改玩法或接口实现。

## 1. P1：整局接口没有接入远征

- 位置：`src/core/run_harness.gd:57`、`:156`、`:179`；`src/tools/run_bridge.gd:43`。
- `reset()` 始终调用 `GameState.start_new_run()`，按 `Database.get_act()` 的旧节点推进，没有创建 `Expedition`，也没有模式分发。
- 实测通过真正的 `run_bridge.tscn` 传入 `{"seed":7,"mode":"expedition","actions":[]}`，输出仍是经典冒险的 `map / 初试 / battle`，唯一动作是 `enter`。直接检查也确认 `GameState.expedition == null`。当前协议没有承诺 `mode` 参数，但也没有其他远征入口；传入它会被静默忽略。
- 缺失范围：迷雾地图移动与拾字、追逐时间、字匣和排版、词谱、印章替换、远征赏 / 谜 / 熔炉 / 商店 / 休息、幕终结算，以及远征战斗的开场和战后分支。

建议：为远征增加整局 harness，由 JSON 桥显式分发模式，直接调用 `Expedition` 的规则方法；战斗进入时复用 `battle_node()` 和 `apply_battle_setup()`，结束时复用 `finish_battle()`。经典模式继续保留，未知模式明确报错。

## 2. P1：需要预先揭示字的词，在自动接口中会被空放

- 位置：`src/core/battle_harness.gd:328`、`:459`、`:498`；对照 `src/screens/battle_screen.gd:998`、`:622`。
- 界面会先揭示袋中字，保存到 `pending_reveal`，再让玩家选择字和位置。harness 只填目标后调用 `try_play()`，没有完成这一准备阶段。
- 定向场景均提供非空字袋、弃字和足够空格，按 `legal_actions()` 返回的词动作执行，结果如下：

| 词 | 实测结果 | 接口返回 |
| --- | --- | --- |
| 火急 | 消耗词字、增加 2 热，日志“补入 0 字”；袋里有可补的字 | `ok: true` |
| 转化 | 默认目标选到施词字，消耗后目标消失；也没有揭示候选字 | `ok: true` |
| 合流 | 自动目标把 `cell1`、`cell2` 都设为同一格，且未提供揭示字的 UID，日志“需要两个相邻空格，未移动” | `ok: true` |

建议：接口显式支持“揭示 → 选择 → 确认 / 取消”，或在执行层完成与界面相同的准备过程。默认自动选择也必须满足真实规则，准备失败应在消耗词字前返回失败。

## 3. P1：特殊战斗阶段没有对应动作

- 位置：`src/core/battle_harness.gd:157`、`:328`。
- 规则层已有实现：`src/core/battle_state.gd:1704` 的 `place_manual_draw()`、`:1678` 的 `resolve_formation()`、`:1815` 的 `do_repeat_rotate()`，但 harness 没有分发这些操作。
- 实测【精心】后结束回合，产生 `manual_draw_pending == 2`，观察和合法动作均不提示；尝试发送选字动作只得到“未选择任何字”。AI 无法完成本应得到的定向补字。
- 实测【转速】只旋转一次，无法通过接口继续发动或选择停止。
- 实测【合击】成功登记，但不能主动发动结阵。结束回合虽会自动结算，无法替代“本回合结算后继续操作”；观察还遗漏了登记队列。

建议：补充定向补字、主动结阵结算、继续 / 结束转速操作，并在相应阶段优先列出可执行动作和当前等待的选择。

## 4. P1：收复的 JSON 嵌套坐标没有转换，会报错后仍返回成功

- 位置：`src/core/battle_harness.gd:361`；`src/core/effect_handlers_actions.gd:576`。
- `_norm_target()` 转换了 `tile`、`tile2`、`cells` 等字段，没有转换 `places` 内的坐标。
- 复现目标：`{"places":[[某枚弃字的UID,[2,1]]]}`。
- 实测执行【收复】时在 `effect_handlers_actions.gd:582` 报 `Trying to assign value of type 'Array' to a variable of type 'Vector2i'`；指定弃字没有返回，外层却仍输出 `ok: true`、空消息。
- 默认自动目标使用原生 `Vector2i`，因此部分内部测试不会碰到这个 JSON 边界问题。

建议：统一递归转换协议坐标，校验完整目标后再消耗施词字。增加一个真正经过 JSON 输入输出的【收复】回归用例。

## 5. P2：observe 缺少决定效果的状态

- 位置：`src/core/battle_harness.gd:96`。
- 字袋和弃字堆仅返回数量，没有通常交互所需的实体列表；只有部分单字动作额外带了候选字。
- 敌人没有状态层数和实体标识；玩家观察也缺少部分减伤、倍率等字段。
- 遗漏当前待选阶段、结阵队列与占用格、转速进度、上次打出的字 / 词、储能消费记录、流速各行预算，以及远征新加的 `pierce_once`、`enemy_skip_turns`。
- 实测给敌人添加 10 层力量，同时设置首次穿盾、敌方跳过行动、上次打出【击】，序列化观察结果完全不变。因此 AI 不能仅凭观察解释这些效果，也不能正确预览【再】等依赖历史的字。

建议：按玩家实际可查询的信息输出状态、实体及候选目标，同时提供必要的历史摘要。不要用整张隐藏地图作为远征的默认观察；完整内部状态可以作为单独的调试输出。

## 6. P2：远征固定种子没有贯通战斗和战利品

- 位置：`src/expedition/expedition.gd:84`；`src/screens/expedition_map_screen.gd:545`；`src/screens/battle_screen.gd:102`；`src/screens/reward_screen.gd:74`。
- `Expedition.start(seed)` 只给远征自己的 RNG 设种子；地图因此可重现。
- 实际开战时没有传入战斗种子，`BattleState.start()` 默认走 `rng.randomize()`。
- 战后三选一使用另一个 `GameState.rng`，它没有被远征种子重置。
- 实测同为 `Expedition.start(7)`，在两种既有 `GameState.rng` 状态下得到相同地图，但奖励分别为“连 / 铸 / 热”和“过 / 冷 / 破”；按当前开战调用方式产生的战斗种子也不同。

建议：把远征种子派生为地图、各场战斗和奖励的稳定随机序列，让 JSON 动作重放能复现整局。观察、合法动作查询和界面刷新不应推进这些序列。

## 7. P2：动作校验与 legal_actions 不一致

- 位置：`src/core/run_harness.gd:221`；`src/core/battle_harness.gd:157`、`:328`。
- 实测地图阶段发送 `{"type":"not_an_action"}`，仍返回成功并进入战斗：该阶段没有检查动作类型。
- 实测【合击】登记后，`legal_actions()` 仍返回同一条【合击】；回填执行则失败，理由是“该字已用于本次结阵”。搜索没有过滤已占用的非共享字。
- 自动测试或 AI 可能把协议错误当成正常推进，也可能不断选择返回列表中的无效动作。

建议：每阶段按白名单验证动作和必需字段；拒绝不支持的类型并保持状态不变。合法动作过滤当前锁定格和实际约束，默认选项需要能直接回填执行。

## 调试命令与文档的补充缺口

- `DebugCommands` 仍主要覆盖战斗和经典构筑，没有远征状态查询、墨 / 时间 / 追逐、字匣 / 版面、印章及指定遭遇的调试命令。`/custom` 也仍重开到经典地图；这不一定要改变，但需注明作用范围。
- README 只说明单场 `agent_bridge`，没有说明已有 `run_bridge`，也没有新远征的自动化入口说明。
- `run_bridge.gd:13` 的默认输入 `tests/run_scenario.json` 在仓库中不存在；使用时必须手动提供输入文件。
