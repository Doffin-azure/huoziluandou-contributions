# 庭院行旅 · 杀戮尖塔式多岔路线草案

- [路线图 PNG](01-sts-garden-route.png)
- [可编辑 SVG](01-sts-garden-route.svg)

## 规模

- 14 个行进层
- 每层 3～5 个节点
- 约 50 个节点
- 6 条从起点到终庭的主路径
- 当前计划路线用橙色实线；其它可达路径用细线

这版不再把整张园林塞进一张空间图，而是把**路线规划**做成《杀戮尖塔》式竖向地图；每个节点进入后再加载一间庭院舞台。

## 规划与改选

- 每层可以重新择路，不提前封路。
- 点击节点只更新“计划路线”，不立即移动。
- 进入节点后，完成该节点内容（战斗胜利、事件结算、商店离开、火堆使用或离开）才提交这一层。
- 未完成当前节点前，可以退回上一层重新选路。
- 已领取奖励、已解决房间不回滚。

## 生成约束

正式生成建议：

| 项目 | 目标 |
|---|---|
| 层数 | 12～15 |
| 节点 | 40～60 |
| 路径 | 5～6 条主路径 |
| 每层节点 | 3～5 |
| 每条路径战斗 | 5～7 场（含首领） |
| 每条路径事件 | 3～5 次 |
| 精英 | 可以被绕开 |
| 保底 | 至少一处宝藏、首领前火堆、可到达商店 |
| 分叉 | 每层至少一个实际可选节点，不用装饰性假分叉 |

生成时先铺路径，再分配房型：先确保连通性和路径数量，再按层带分配战斗/事件/商店/火堆/宝藏/精英，最后校验每条路径的预算。

## 和园林美术的关系

这张图是**规划层**，不是整园可行走图。进入节点后：

- 只加载当前节点对应的房间舞台；
- 战斗、事件、商店、火堆、宝藏继续使用现有房间模型和面板；
- 不再需要全图 fog mask、全图相机、全图懒加载和全图阴影同步。

这样规模可以做到 50 个节点以上，而不会让空间排列和性能一起失控。
