# 庭门选路与桥廊接入

在 `codex/courtyard-room-map` 工作树实现。保留当前幕的 55 个候选节点、逐格行走和不可回头规则。

## 实际游玩

- 默认进入三维庭院。点击地砖四向逐格行走，也可以直接走进出口；跨出门槛后，原有单向门规则关闭回路。
- 庭门附近标出目的节点的类型和它后面可选的类型。点标记可查看实际行走路线，再点标记或“走这条路”前往；查看信息本身不推进节点。
- “路线图”随时打开整幕布局，仍可预选到首领。预选中的下一庭以菱形标识；只走本次选择的路，不自动执行后续节点。
- 战斗、商店、事件和奖励返回后恢复原庭院与机位，不再强制打开选线图。已有节点界面和地图实例缓存继续使用。

## 实际装配

旧紧凑庭院曾绕过 `GardenBridgeNetwork`，旧桥网又假定 0.25 米细网格，不能直接挂回 1 米格地图。本次增加 `garden_compact_passages.gd`，从同一份实际通路计算装配位置。

- 复用 `garden_bridge_kit.gd` 的连廊、廊桥、石拱桥、柱桥、栏杆和栏柱。长直段使用连续屋顶，不连续叠小亭顶。
- 建筑包围范围避让房间、其他桥廊和不相关通路。地面保持同一高度；石拱位于平桥面下方，不改变拾取或行走坐标。
- 桥下去掉原先遮住墩柱的实心路基侧面，保留原地砖顶面。沿水裸路补连续栏杆，直线和转角共用栏柱；跨区域接缝也分配明确的柱子归属。
- 仅抬高廊顶及承顶木构，为现有人物留出净高；栏杆与路面接高保持一致。
- 桥廊参与屋顶遮挡处理、附近灯光预算、区域装配与缓存回收。重复模型经网格库烘焙共享，栏杆按区域合并；装饰不使用玩法随机数。

现有石拱桥采用平桥面、下部拱券的形式，本次没有增加高低行走或曲面桥面。桥廊按符合净空的直段装配，尚未把整张地图改成连续带顶回廊。
