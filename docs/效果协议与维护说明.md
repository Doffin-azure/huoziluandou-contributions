# 效果协议与维护说明

本次统一战斗效果的分类、目标候选、出字预检、说明和只读预览。现有 `.tres`、handler 名称和战斗结算顺序保留；内置效果逐步迁移，新效果可以通过注册定义接入。

这是一层维护与扩展接口。目前没有创意工坊下载、模组加载、依赖管理或存档版本迁移。遗物的战斗开始／回合结束等生命周期事件也留待遗物接入时单独实现。

## 职责与调用顺序

| 文件 | 职责 |
|---|---|
| `src/core/effect_registry.gd` | 效果定义注册，分类、目标规则、说明、预览和执行的统一入口 |
| `src/core/effect_targets.gd` | 目标候选、坐标规范化、多阶段揭示准备、内置目标校验及默认目标 |
| `src/core/play_request.gd` | 只读出字预检，供界面、AI 与正式出字复用 |
| `src/core/effect_descriptions.gd` | 实时预览与已有状态提示，不执行效果 |
| `src/core/battle_state.gd` | 真正消费实体、支付、执行及结阵队列管理 |
| `src/core/effect_handlers*.gd` | 现有内置效果的执行实现 |

常规调用顺序：

1. `battle.play_options(path)` 查询交互类型、候选及目标要求。
2. 有揭示步骤时调用 `battle.prepare_interaction(path)`；此时才实际取出字。
3. 界面或 AI 提交目标，通过 `battle.inspect_play(path, target)` 预检。
4. `battle.try_play(path, target)` 再次校验，然后执行或登记结阵。
5. 结阵发动时根据当时盘面、资源重新校验，通过后才消耗材料。

`EffectPreview`、`EffectHandlers.run()` 以及旧单字目标辅助函数保留为兼容入口，并转发到公共接口。界面主要负责选择浮层和输入表现，正式目标合法性由公共校验决定。

## 注册新效果

新增脚本效果使用 `包名:效果名`，例如 `my_pack:guard`。注册必须在该效果首次使用前完成。扩展不能用旧内置名称隐式覆盖效果，重复注册返回 `false`。

```gdscript
static func register_effects() -> bool:
	return EffectRegistry.register_handler("my_pack:guard", {
		"kind": EffectData.Kind.BLOCK,
		"execute": func(effect: EffectData, ctx: Dictionary) -> Array:
			ctx.battle.player.add_block(effect.amount)
			return ["获得%d临时格挡" % effect.amount],
		"describe": func(effect: EffectData) -> String:
			return "获得%d临时格挡。" % effect.amount,
		"preview": func(effect: EffectData, ctx: Dictionary) -> String:
			return "当前临时格挡%d；本次获得%d。" % [ctx.battle.player.block, effect.amount],
	})
```

资源中设置 `handler = "my_pack:guard"` 和 `amount`。`CharacterData.solo_effects`、`WordData.effects` 都可引用。新增字词本身仍需要被 `Database` 加载；注册效果不自动创建或安装字词资源。

| 定义字段 | 类型／约定 |
|---|---|
| `execute` | 必填有效 Callable：`(effect, ctx) -> Array`，返回结算消息 |
| `kind` | 可选 `EffectData.Kind`，用于攻击识别、说明回退和 AI 评分；新效果应明确填写 |
| `required_target` | 可选 `EffectData.Target`，例如 `BOARD_TILE`、`BOARD_ROW` |
| `interaction` | 可选 String，选择已有的界面交互流程 |
| `needs` | 可选 String，词语的默认选目标类别，通常由交互类型推导 |
| `validate` | 可选有效 Callable：`(effect, ctx) -> String`，合法返回空字符串，否则返回错误原因 |
| `targets` | 可选有效 Callable：`(effect, ctx) -> Dictionary`，返回 `cells`、`cards`、`default` |
| `preview` | 可选有效 Callable：`(effect, ctx) -> String`，返回实时补充说明 |
| `describe` | 可选有效 Callable：`(effect) -> String`，返回静态效果说明 |

查询回调的 `ctx` 含 `battle`、`path`；校验和预览还含 `target`。执行时另有 `source`、`glyphs`、`word`、`target_index`、`consumed` 等上下文。`pre_consume` 效果执行时材料尚未消耗，`consumed` 为空。

`targets` 只允许补充候选与默认目标，不会覆盖系统算出的词语、交互类型、目标要求。多个效果提供同一候选字段时，后一个覆盖前一个；复杂复合效果应由一个回调统一给出候选。

候选示例：

```gdscript
"targets": func(_effect: EffectData, ctx: Dictionary) -> Dictionary:
	var cells: Array = []
	for i in ctx.battle.board.cells.size():
		var c: CharInstance = ctx.battle.board.cells[i]
		var pos: Vector2i = ctx.battle.board.to_xy(i)
		if c != null and not c.pinned and not ctx.path.has(pos):
			cells.append(pos)
	return {"cells": cells, "default": {"tile": cells[0]} if not cells.is_empty() else {}}
```

对应的 `validate` 必须检查目标仍存在、是否固定、是否为施词实体及其他效果条件。候选用于辅助选择，最终合法性由校验决定。候选格用 `Vector2i`；`cards` 用原 `CharInstance`，默认目标用 Dictionary。

界面可直接复用现有选格、选行、选字袋／弃字等流程。全新交互形式仍需增加对应控件，注册一个陌生 `interaction` 名称不会自动生成界面。

## 必须遵守的规则

- `targets`、`validate`、`preview`、`describe` 都是只读查询，不得取字、洗牌、消费随机数、创建实体、扣费或增减状态。当前通过约定与测试保证，没有脚本沙箱隔离。
- `validate` 可能被多次调用；只有 `execute` 可以改变战斗状态。重演、超载等机制可能按规则再次调用 `execute`，不能用查询次数控制效果。
- 注册的 `kind` 才是 handler 效果的语义分类。`EffectData.kind` 的历史默认值为 DAMAGE，不应让非攻击效果因此被误判为攻击。
- 同字形可以对应多个实体。选择原实体用 `uid` 区分，多个目标须去重；不能只按字形判断。
- `EffectData.note` 优先于注册的静态 `describe`。词语完整说明、单字的 `description` 和 wiki 精简词条仍可保留策划文案，实时计算放到 `preview`。
- 现有原名 handler 继续走内置兼容分支。引用未注册的命名空间效果会在正式消耗前拒绝，并返回明确错误。

## 揭示、取消与结阵

目前【转化】【火急】【合流】使用公共揭示准备流程。`prepare_interaction` 会先检查材料与盘面，再保存施词路径、实体 UID 和揭示字；重复准备同一次选择不会重抽。取消调用 `battle.return_pending_reveal()`，归还字并清理选择状态。

当前选择尚未完成时，不能改为打出另一条路径或发动结阵。结阵登记后，每条队列条目独立持有自己的揭示字；确认执行后不会被下一次准备覆盖。落点失效或结阵提前结束时，未使用的揭示字返回字袋。

低层 `reveal_from_bag()` 保留用于兼容。新增界面／AI 流程应调用 `prepare_interaction()`，以获得一致的准备校验与施词实体检查。

## AI 与 JSON 接口

`BattleHarness` 的原 `reset/observe/legal_actions/apply` 调用方式保留，补充以下动作：

| `type` | 参数／作用 |
|---|---|
| `inspect_play` | `path`、可选 `target`；只读返回合法性、候选、默认目标、实时预览及是否需要准备 |
| `prepare_play` | `path`；显式取出待选揭示字，结果从 `observe().pending_reveal` 读取 |
| `play` | `path`、可选 `target`；目标省略时按公共默认策略选择，必要时自动准备揭示 |
| `cancel_choice` | 归还正在选择的揭示字；没有选择时返回失败 |
| `manual_draw` | `glyphs`；完成【精心】补字；`[]` 表示随机补齐剩余额度 |
| `resolve_formation` | 发动已登记的结阵，保持同一回合；效果要求结束回合时会正常推进 |
| `repeat_rotate` / `end_repeat_rotate` | 继续／结束【转速】 |
| `end_turn` | 结束回合；待选揭示字未处理时返回失败 |

`legal_actions()` 查询不揭示字、不洗牌；它按当前默认目标给出可执行出字建议，词路数量仍受原有搜索上限限制，不是所有目标组合的穷举。需要自行选择目标时先查询 `inspect_play`。未知动作会返回失败。

外部坐标使用 `[x, y]`，原生调用可使用 `Vector2i`。JSON 中整数会被 Godot 解析成浮点数，规范化接口接受整数值浮点坐标；非法坐标保留为无效哨兵，不会误选左上角。目标字段按现有协议：

- 单格：`{"tile": [2, 1]}`；双格：`tile` / `tile2`。
- 行：`{"row": 1}`；多选：`{"cells": [[0, 2], [1, 2], [2, 2]]}`。
- 【火急】两个落点：`{"cell1": [0, 2], "cell2": [1, 2]}`。
- 【收复】实体与落点：`{"places": [[字的UID, [0, 2]]]}`，UID 和落点均不可重复。
- 字袋／弃字：按效果使用 `bag_uid` / `place_uid` 等实体字段；可从 `inspect_play` 与 `observe` 返回值读取。

`observe` 补充弃字实体、待选揭示字、精心待补额度、结阵队列与保留格、转速进度、重连暂存实体等字段，原有字段保持兼容。外部桥仍以固定种子和完整动作序列重放单场战斗；跨幕路线、奖励、商店等远征决策接口未在本次加入。
