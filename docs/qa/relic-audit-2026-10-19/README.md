# 15件遗物逐件逻辑验收

环境：Godot 4.7.2、Windows桌面headless。测试运行独立场景，未启动手机调试、未构建APK。

## 本次发现与修复

“精心”把基础补字交给玩家选择，但补字后的遗物钩子原来仍在回合开始时立即执行：

| 遗物 | 修复前 | 修复后 |
| --- | --- | --- |
| 净版布 | 选字前就随机补一枚；随后选入污染字也已获得奖励 | 先完成补字，再按落盘后的污染状态决定是否奖励 |
| 转轮架 | 选字前消耗方向，所选字落盘后不参与重力 | 所选字落盘后转动一次，方向顺序保留 |
| 压字石 | 手动选入的绑定字可能停在非底行；8个固定落点种子中5个失败 | 手动补字结束后立即结算下落，8个种子全部通过 |

三者同属“基础补字完成后”的时序路径。只调整 `BattleState` 的钩子调用时机；普通补字顺序、零额度补字、遗物数值、存档字段保持原有契约。生产补丁相对本次开始时的文件为12行新增、8行移除，原有日志等修改保留。

修复前边界测试：47通过、9失败；修复后：56通过、0失败。三段攻击测试使用真实 `damage_multi` 处理器及 `args.hits`，没有把不生效的旧 `EffectData.hits` 当成游戏缺陷。
