# 护盾与状态栏布局验收

## 结论

护盾组件原来按当前显示的盾数量返回宽度，玩家和敌方血条都用该宽度计算位置，导致加盾、破盾、清空时血条移动或缩短。现固定预留两种护盾槽，单盾右对齐；血条及生命数字位置、宽度稳定。

状态栏为单行 `StatusStrip`，不会自动换行。按可用宽度计算容量，溢出时留一个“更多”（省略号）入口，点击查看全部状态与说明。无需修改其原有交互。

生产修改仅 `src/ui/defense_display.gd`，新增3行、移除1行；没有修改护盾结算或整体配色、布局。

## 验证

Windows / Godot 4.7.2。截图来自桌面原生渲染窗口，以横屏尺寸模拟布局，未启动手机调试、未构建APK。

| 检查 | 修复前 | 修复后 |
| --- | --- | --- |
| 60项HUD几何检查 | 36通过、24失败（加盾后的血条和数字位置改变） | 60通过、0失败 |
| 玩家状态HUD既有检查 | — | 30通过、0失败 |
| 战斗UI原生检查 | — | 60通过、0失败 |

有效验收合计150项通过。覆盖0盾、单临挡、单持久盾、双三位数盾、归零；玩家和敌方分别比较血条/生命数字矩形；大量实际能力折叠并打开完整详情；状态图标不越界。容器最小高度38.4→39等小于1界面像素的取整不算换行。

`battle-ui.log` 是额外headless运行，四项鼠标坐标检查失败；该场景没有设置初始窗口尺寸，不适用于headless默认小窗口。按适用的桌面原生窗口复验，`battle-ui-native.log` 的60项全部通过。没有因此修改字盘输入逻辑。
