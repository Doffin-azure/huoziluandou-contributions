# 《活字战斗》（暂定名）

**Game Design Document · Godot 4.x 开发基准 · V0.1**  
**日期：2026-10-10｜阶段：立项与纵向切片设计｜主平台：PC，键鼠优先**  
**设计原则：规则明确优先于特效华丽；游戏化布局优先于网页仪表盘；词语必须真实、玩法必须可解释。**

> **阅读约定：**【确定】代表已反复明确的基础设计；【方案】代表适合第一版实现但尚需测试；【待定】代表不能由程序员自行脑补；【原型占位】代表 P25/P26 为跑通流程临时采用的规则。此文档是可执行的开发基准，**不是 104 个词效已经全部定稿**。

---

## 0. 项目摘要 / One-page Pitch

**一句话玩法：** 玩家管理一袋会循环出现的实体汉字，在 **4×4 字盘**上按上下左右连接字块，拼出真实中文词语，以词义触发攻击、防御、改盘、抽字、经济、储能和透支等效果；战后通过加字、删字、复制、商店和修饰逐渐改变自己的“可组词概率”，完成 Roguelike 冒险。

**真正的核心乐趣**不是看词语播动画，而是：

1. **空间找词：** 同一组字位置不同，可连出的词不同；重力、回转和指定落点会改变局势。
2. **实体字经营：** 一枚【击】拿去打【反击】，就暂时不能用于【重击】【合击】；删除、重复、收购改变整局词网。
3. **跨词组合：** 有些词改变后续的行动规则，例如【合击】共享一个【击】、【重合】堆叠临时使用次数、【流转】奖励不同词连续使用。
4. **取舍与反噬：** 高速循环产生自我污染；敌方污染字可用于组词，但打出要付出代价。

**定位：** 单人、策略、回合制、2D、以中文词语为可执行操作的轻量 Roguelike。美术可以抽象、现代、有梗，**不采用印刷厂或传统活字印刷世界观**。玩家操作的是字盘，游戏系统负责解析和结算；不需要接入在线大语言模型来判断每一步。

**首版开发目标：** 在 Godot 中完成一场可赢、可输、规则可回放的战斗，再拓展为包含战后奖励、商店、三至五场战斗的纵向切片。全词表、分支地图、正式美术与高难 AI 留到之后。

## 1. 设计边界：哪些规则不能在开发时改掉

| 事项 | 基准规格 | 状态 |
|---|---|---|
| 战斗棋盘 | 4 行 × 4 列，共 16 格 | 【确定】 |
| 连线方向 | 仅四邻接：上、下、左、右；可转弯，不可同一路径重复同格 | 【确定】 |
| 词语长度 | 优先支持 2～4 字合法中文词；单字单独使用 | 【确定方向】 |
| 单字操作 | 单字“出牌”与“弃字”是同一操作；无单字效果也可打出 | 【确定】 |
| 无效多字路径 | 不执行、不消耗任何字、不扣行动次数；仍可修改选择 | 【确定】 |
| 正确词语 | 成功路径消耗实体字并触发词效；有些合法词是否可作为零效词使用见待决项 | 【确定框架 / 待定边界】 |
| 一回合行动数 | 无固定出字次数上限；受字袋、空格、位置和资源制约 | 【确定】 |
| 补字 | 回合开始时基础补字暂定 3；有空格、抽字来源才补得进去 | 【方案】 |
| 初始盘面 | 标准样例：在 4×4 中随机落下 12 枚己方字；其余为空 | 【方案】 |
| 初始字袋 | 当前建议约 16 枚实体字；P25 测试用了 18 枚，**不能直接当正式初始牌组** | 【待测试】 |
| 战斗流转 | 已消耗的己方实体字进弃字堆，抽字袋耗尽才洗回 | 【确定】 |
| 出字后空位 | **不自动补满**；必须等待回合基础补字或明确的补字词效 | 【确定】 |
| 临时格挡 | 默认本回合/敌方行动的格挡；跨回合持久护盾单独计算 | 【确定方向】 |
| 敌方污染 | 敌人注入的字块可以组词，打出时付出污染代价；消耗后从场上消失 | 【确定框架】 |
| 过热 | 热度超过热容后，每点溢出向本场抽字袋塞入 1 枚带“灼热”污染的【热】 | 【最近讨论方向，数值待测】 |
| 冒险成长 | 战后三选一，提供加字、复制、删字、修饰、治疗等选择；商店用金币消费 | 【确定方向】 |

**注意：** P26 HTML 概念版的“5×5、随机字池无限填盘、打出任何无效组合也会消耗”，都**不是**正式游戏规则，不应照搬进 Godot。

## 2. 玩家操作与回合节奏

### 2.1 一次出字的生命周期

1. 鼠标按下/触摸开始于一个有字的格子，记录首格；拖过四邻接格时延长路径。
2. 拖动过程显示路径光线、当前字串、词语识别状态、**根据当前真实战况计算的预计效果**。
3. 移回路径倒数第二格可撤销末一格；滑出盘面则保持当前合法路径，不应误选远格。
4. 松开/点击确认后校验：
   - **单字**：允许出字，结算该字已定义的单字效果（没有则只消耗）。
   - **合法有效词**：结算词效，并按正常规则消耗参与路径的实体字。
   - **未识别多字组合**：撤销本次选择，盘面不变；显示轻量“不是合法出字路径”提示，**不播放“出字无效果”的梗图**。
   - **合法但零效的词**：这类词是否允许主动出掉尚待确定；若开放，则正常消耗并触发梗图。
5. 同一次动作中若有污染字，被消耗时附带触发污染代价。结算结束后更新盘面、状态、日志与敌方血量。
6. 玩家可继续组词、打单字或主动结束回合。

### 2.2 回合顺序（首版建议）

| 阶段 | 执行内容 | 说明 |
|---|---|---|
| 回合开始 | 结算补字修正，尝试从字袋随机落入 3 枚己方字 | 空格不够就只补实际可容纳数量 |
| 玩家操作 | 任意次数使用单字、有效多字词；可主动结束 | 不设人工行动力值 |
| 玩家结束 | 检查【蓄能】等留词收益，准备敌方行动 | “留在盘面的有效词”可以有收益 |
| 敌方行动 | 执行预告的攻击 / 注入字 / 限制手段 | 应先让玩家看见预告，便于筹划 |
| 后置结算 | 【反击】等延迟状态结算、持续状态衰减、清除临时格挡 | 永久与持久护盾不在这里删除 |
| 轮次推进 | 更新敌方下一次行动意图；进入下回合 | 每一阶段写进统一事件日志 |

**必须统一的结算约定：** “先消耗、再触发词效，再触发自动能力，最后按顺序补字”的基准可用，但【重击】必须在消耗后做一次重力下落并统计移动字数；【回】要在原位置换字；【合击】会特殊处理共享实体【击】。这些词在词效系统中要能声明特殊步骤，不可被一个死板函数顺序绑死。

### 2.3 单字与空格

单字是可打出的实体，不另设“免费删除格子”按钮。无效果单字也能腾空间，但会真实减少当前盘面字数、进入弃字循环；面对污染字时，还可能扣血或削弱补字。盘面可能被耗空，这是游戏要面对的资源压力，而不是自动填满的 UI 错误。

## 3. 字块的数据定义与存储规则

**一个实体字块必须有独立 ID，字形只是其中一个属性。** 同一个【击】可能同时出现多个所有权、污染和叠层状态，不能只在 GridCell 中存字符串。

建议 `GlyphInstance` 保存：

| 字段 | 作用 |
|---|---|
| `id` | 全局唯一实体实例号，便于记录与回放 |
| `char` | 单个汉字，如 `击` |
| `owner` | `PLAYER`、`ENEMY`、`SELF_GENERATED`（本场自生污染） |
| `pollutions` | 零个或多个附着状态，如灼热、虚弱、减抽 |
| `modifiers` | 冒险获得的额外修饰；不等于污染 |
| `temporary_uses` | 原格上可额外使用几次的**非实体复制层** |
| `location` | `BAG` / `DISCARD` / `BOARD` / `CONSUMED`，始终唯一 |
| `cell` | 若在字盘，保存 (row,col)，否则无位置 |

**关键所有权原则：** 敌方字即使被净化也只是去掉污染，不会自动进入玩家字袋。敌方字消耗后消失；【收购】才执行“敌方实体转为玩家永久实体”。自我过热生成的【热】可以在本场字袋/弃字堆中循环，战后清理；是否改为跨战保留另议。

### 3.1 【重合】属于字盘实体守恒的特殊机制

例如盘面有 4 个玩家实体【击】：

- 玩家指定其中一个**已有的【击】格**作为汇聚点。
- 该格保留 1 个真实实体，并获得对应原来总数的 4 次可用层数（等价为 1 个真实 + 3 次临时使用）。
- 其余 3 个真实实体【击】**立即洗回抽字袋**，不是进入弃字堆，也不是永久删除。
- 打出叠层上方的临时次数，只减少层数，不进入弃字堆；最后一次才把保留实体按正常规则消耗。
- 其他格因此变空，可能改变补字的未来落点；抽字袋反而更容易抽到【击】，有意稀释其他字的抽取比例。

**Godot 必须测试：** 当一个叠层格仍有未消耗层数时，任何“原地换字”效果不能把其他汉字硬塞进同一个格子。需用选择失败、延迟替换或指定额外空格等明确分支处理。

### 3.2 污染与自我过热

- 污染是字块状态，**不改变汉字本身**；污染【击】仍可连成【反击】。
- 污染字独立于正常词效触发负面代价：无论它单字打出或参与多字词。
- `灼热(热)`：超过热容每点溢出制造 1 枚附带灼热污染的【热】，进入本场抽字袋；打出时损失生命的具体数值暂定 1，仅用于首轮体验测试。
- 【冷却】预防继续生成灼热字；【清热】可以负责清理已形成的灼热污染；【清洗】负责一次净化多枚污染标记。这三类作用不应重复。
- 净化保留字形、位置与原所有权，只移除负面标签。是否能净化抽字袋内部的字，需由词效明确写出范围。

## 4. 词库分层与词效设计策略

### 4.1 词语判定必须与效果分离

分三层：

1. **自然语言词表**：哪些 2～4 字字符串算有效中文词，需人工审核自然性。它不能直接决定造成几伤。
2. **技能效果表**：每条已制作词的 `word_id`、行为类型、数值、操作选择与触发状态，可热更新和自动测试。
3. **特效表现表**：发光线条、音效、梗图、屏幕震动等只负责展示，不可决定战斗结果。

第一版不需要在线 AI 负责判词：离线 CSV/JSON/Resource 词表更公平、更可测试，也能避免同一个词不同局产生不同解释。“模型自己拼字执行”应体现为**玩家连词后游戏系统统一解析并执行**的游戏体验，而非强制加入联网 AI。

### 4.2 六类互相联动的构筑引擎

| 系统 | 玩家经营的资源 | 代表词 | 独特选择 |
|---|---|---|---|
| 防反 / 护盾 | 临时格挡、跨回合持久护盾、受击反击 | 防御、防护、护盾、反击、防御力、盾击 | 留盾保命，还是消耗护盾进攻 |
| 空间连携 | 上一个即时攻击、共享实体字、重力位移、复制层 | 连击、合击、重击、重合、回转 | 哪个词先打、哪个字先保留 |
| 补字流转 | 空格、抽字袋、弃字堆、定点落字 | 回流、回收、流转、投放 | 当前刷新速度 vs 未来抽字质量 |
| 储能蓄放 | 存在当前场次的储能 | 蓄能、蓄电、充电、放电、充放电 | 保留现成词等待 vs 立即兑现 |
| 热度透支 | 热度 / 热容 / 灼热污染字 | 加速、过载、冷却、重载、火爆、清热 | 快速循环 vs 长期字袋污染 |
| 经济构筑 | 金币、临时资金、拟议股权、商店购买力 | 金币、投币、收购、投放、投资、复利投资 | 本战救命 vs 战后成长 |

原 P23 有 **51 个候选汉字、104 个候选多字词**，属于词网素材，不是完成的技能库。P25 引擎覆盖受控子集，有部分程序占位。建议首个 Godot 战斗只移植 **12～20 个经过核对的词**，先保证一个词的所有结算细节正确。

### 4.3 第一场战斗建议优先进入的词（方向和数值分开）

| 词 | 先实现的概念效果 | 开发核查点 |
|---|---|---|
| 单字【防】 | +4 临时格挡 | 回合末衰减正确 |
| 单字【护】 | +2 持久护盾 | 跨回合保留正确 |
| 单字【击】 | 造成 4 伤害 | 攻击触发记录正确 |
| 单字【回】 | 消耗后原位置随机换字 | 空袋/叠层/污染兼容 |
| 防御 | +10 临时格挡 | 正式结算与预览一致 |
| 回防 | +8 临时格挡；此前有其他即时攻击则补 1 字 | 条件按事件发生顺序判断 |
| 反击 | 挂临时状态；敌人整次行动之后消耗剩余临挡并回击 | 与【合击】队列相容 |
| 重击 | 6 伤害 + 重力移动的每枚字 2 伤害 | 移动“字块次数”去重 |
| 击破 | 击碎敌盾后补字 | 敌盾与血伤分段记录 |
| 连击 | 重演上一次即时攻击词**效果**，而非仅重放数字 | 防止复制自身无限递归 |
| 回流 | 消耗词字，随机补入至多 4 字 | 非定点、受空位和库存约束 |
| 重合 | 汇聚同字复制层 + 实体字回抽字袋 | 守恒、层数、重复使用 |
| 清洗 | 解除当前字盘的污染标记 | 敌方字不自动变己方 |
| 加速 | 每次有效多字词后补字并升温 | 自我污染链能看到 |
| 冷却 | 降低当前热度 | 不删除已生成灼热字 |
| 金币 | 获得金币 | 收入反刷约束另行确认 |
| 投币 | 花金币换即时伤害 | 玩家支付数量 UI |
| 投放 | 随机揭一枚实体字，由玩家指定空格 | 不能预知抽字结果做非法选择 |

**非首版但值得保持：** 【合击】共享击的批量队列、【防御力】跨冒险永久减伤、【复利投资】四字永久经济效果。它们需要专门的调试场景，不能因为第一局抽不到而被判断为“没价值”。

## 5. 战斗敌人与污染玩法

**首版敌人只需有可预测的 3 种行动**，但每种能迫使玩家作出不同选择：

- **攻击**：明确展示“本回合结束后攻击 7”等意图，玩家可以用【防御】或【反击】应对。
- **插字**：往有空格的盘面插入 1 枚敌方实体字，可能附带污染；只能占据允许的位置，不能无预告覆盖己方字。
- **强化 / 护盾**：给敌人护盾或准备下一次强攻击，使【击破】【破甲】有目标。

首版污染先用 2 类便于辨识与测试：

1. **刺痛**：打出这枚字时失去 2 生命（受护盾/永久减免影响与否待定，但必须在文案中写清）。
2. **堵塞**：打出这枚字后下一次正常补字数量 −1（一次性，不能无限叠加成负补字）。

“玩家主动把污染字打掉”和“把它并入强词一起打掉”都应是合理选择，但会付代价；【清】可能净化一枚正交相邻字，【清洗】净化全盘，具体仍需试玩。

**敌人不负责偷偷改词典。** 如果要做“字被封印、词义改变”之类高阶敌人，必须在 UI 预告其规则变化。

## 6. Roguelike 大循环

**首轮纵向切片建议 5 场战斗**；前 1～2 场是教学和基本构筑选择，第 3～4 场加入污染与热度，第 5 场 Boss 检验构筑链条。长度只是测试安排，不是最终章节数量。

### 6.1 冒险流程

```
初始实体字袋（约 16 枚）
    ↓
战斗：随机落字 → 连词 → 结算 → 敌人行动
    ↓ 胜利
三选一：增加新字 / 复制已有字 / 删除字 / 修饰字或词 / 恢复生命
    ↓
商店（按路线间隔开放）：支付金币进行买字、删字、购买修饰等
    ↓
下一战：继承生命、金币、字袋、永久修饰与永久能力
    ↓
第 5 战 Boss → 结算 / 重开新一局
```

### 6.2 战后奖励要有真实取舍

| 奖励 | 立刻得到 | 真正的代价 |
|---|---|---|
| 新增字 | 更广的词网，解锁此前不能组成的词 | 抽字比例更散、牌袋变厚 |
| 复制字 | 提高关键词【击】【回】等抽到概率 | 可能稀释其他词的连接需求 |
| 删除字 | 提高剩余核心字出现率 | 可能彻底失去三字词的某一个字 |
| 修饰字 | 增加用途、减少污染、改变重力等 | 放弃本次加字与删字机会 |
| 回血 | 提高当前冒险存活率 | 牺牲未来构筑成长 |

必须能让玩家在选择奖励前查看字袋成分，以及一个字目前能和自己已有字组成哪些候选词。**禁止 UI 把删字包装成永远划算。**

### 6.3 货币边界

金币是一种**可带到战后商店**的资源，因此战内可循环刷钱会破坏整局平衡。P25 曾暂以每战金币收入上限 18 作为保护栏，**不是正式规则**。正式版需在以下方案中择一测试：经济词同场递减收益、单战现金收入软上限、具有战斗风险的经济动作，或关卡限时压力；不要悄悄保留某个隐藏硬上限。

股权、复利与跨战再投资属于进阶经济词，待基础商店购买价值稳定之后再开放。

## 7. UI/UX：真正的游戏战斗屏，而不是网页

**总体原则：字盘是主角。** 以 16:9 PC 横屏、1920×1080 设计基准，最小 1280×720 时需要保证汉字不拥挤。主要场景常驻信息应不超过：当前战况、字盘、当前正在连的词与预计后果、结束回合。

### 7.1 屏幕区域方案

| 区域 | 建议 | 一直显示？ |
|---|---|---|
| 顶部 10%～14% | 玩家 HP / 持久护盾 / 回合 / 敌人 HP / 下次行动意图 | 是 |
| 中部核心约 50%～60% 的视觉注意力 | 放大 4×4 字盘，每格完整命中区域；拖线覆盖其上 | 是，最高优先级 |
| 字盘侧边随手势展开 | 当前字串、有效性、预计伤害/格挡/目标、污染代价 | 连字时显示；平时可折叠 |
| 角落轻量帮助 | 蓝色大肥鱼图片仅在适合的时刻出现提示，不当角色立绘常驻占地 | 触发时 |
| 底部紧凑操作区 | 已选路径、撤回/取消、结束回合、可打开字袋与词典 | 是，避免铺开大量按钮 |
| 图鉴/日志/字袋 | 以抽屉或覆盖层打开，不常驻霸占半屏 | 否 |

**不照搬先前生图中的“海洋、鲸鱼、水属性”等词效。** 那些是氛围概念，不在 P23 的初始 104 词规则里，不能当成策划案承诺。场景美术不绑“印刷世界观”，也不需要围绕梗图塑造英雄角色。

### 7.2 关键交互状态机

| 状态 | 视觉反馈 | 允许输入 |
|---|---|---|
| IDLE | 字盘正常显示；可组词轻微提示可关闭 | 开始拖动、单字、结束回合 |
| DRAGGING_UNKNOWN | 选中格高亮、线段跟手；当前字串更新 | 继续拖、回退、取消 |
| DRAGGING_VALID | 预览实时显示词名、词效及涉及污染惩罚 | 继续拖、回退、松手 |
| DRAGGING_INVALID | 低对比度提示“未识别”；**不消费字** | 继续拖、回退、松手取消 |
| RESOLVING | 短暂播放字块消耗、数字变化、补字；禁用二次输入 | 无 |
| NO_EFFECT_FEEDBACK | 使用无效果的单字或正式允许的零效果词时，短暂弹梗图 | 不应阻塞后续操作 |
| ENEMY_TURN | 敌人行动和污染入盘动画；下一步预告更新 | 暂停玩家拖动 |

### 7.3 两张梗图如何使用

- **蓝色大肥鱼（图 1）**：出字路径已识别、效果已计算时，在侧边小浮层作为玩梗“预览表情”。**真正重要的文字说明仍需独立显示**，不允许仅靠梗图传达伤害或代价。
- **惊讶反应图（图 2）**：玩家确实打出一张无效果的字/零效合法词时弹出 **0.4～0.7 秒**；有冷却/连播抑制，不能连续闪烁挡住字盘。
- **无效多字组合**：根本不出字，所以只能轻微抖动或提示“未形成有效词”；不能播放“已出字但无效果”的反应并消耗实体字。
- **图片版权：** 当前两张由用户提供，适合内部概念验证；如正式商用，应确认授权或替换为原创等价演出。

### 7.4 连字手感验收标准

- 字块正交连接可准确拖过，不能跨空格、斜连或绕开缺字格。
- 回拖到前一个格子取消末字；移出盘面不误提交；松手/失焦有确定行为。
- 连字时不等待词效动画：预计效果在拖动过程中即时变更。
- 预览必须考虑当前护盾、已叠加状态、敌人弱点和污染代价，不显示固定假数字。
- 鼠标输入与触屏输入从同一接口转换成盘面坐标，输入层单独测试。
- 4×4 每格分辨率允许放大；在 1280×720 下主要汉字清晰可辨，字号自动缩放。

## 8. Godot 4.x 技术策划

**建议使用 Godot 4.6 稳定系列 + GDScript**，以 2D 场景为主。第一阶段 PC；预留触摸但不要一开始就为手机调整游戏规则。确认团队所装 Godot 的具体小版本后锁定工程版本并统一导入。

### 8.1 场景树草图

```text
Main.tscn (Control)
├─ BattleScene.tscn (Control)
│  ├─ CombatHUD (Control)
│  ├─ Battlefield (Control/Node2D)
│  │  ├─ BoardView (Control)         # 16 格展示与坐标转换
│  │  ├─ GlyphTileView × 16          # 每格背景/汉字/污染角标/层数
│  │  └─ DragPathOverlay (Node2D)    # 选中路径、连接线、跟手光点
│  ├─ WordPreviewPanel (Control)     # 词效真实预估
│  ├─ ActionBar (Control)            # 取消/结束回合/打开字袋
│  ├─ EffectPlayer (Node)            # tween、音效、镜头反馈
│  └─ ReactionOverlay (CanvasLayer)  # 两张梗图，非阻塞
├─ RewardScene.tscn
├─ ShopScene.tscn
├─ BagInspectScene.tscn
└─ RunSummaryScene.tscn
```

### 8.2 推荐脚本职责

| 单元 | 主要职责 | 禁止做的事 |
|---|---|---|
| `BattleState` | 持有 16 格、牌袋、弃字堆、HP、盾、热容、状态、事件序号 | 不直接改 UI 标签 |
| `GlyphInstance` | 唯一实体字、所有权、污染、临时层数 | 不负责播放音效 |
| `WordLexicon` | 查自然词、合法性、词效 ID | 不给 UI 直接造成伤害 |
| `PathController` | 把鼠标/触屏轨迹转换成合法格索引路径 | 不结算战斗伤害 |
| `ActionResolver` | 按确定顺序执行完整的出字事务 | 不依赖动画结束判定规则 |
| `EffectRegistry` | 根据数据表调用小型、可测试的效果处理器 | 不把每个词写在一大段 if-else |
| `DrawBag` | 实体进出、洗牌、抽取、去重与可追踪 RNG | 不静默创造缺失实体 |
| `EnemyBrain` | 选取动作、生成意图和目标合法性校验 | 不绕过 ActionResolver 改盘 |
| `CampaignState` | 跨战生命、金币、永久字袋和修饰、节点进度 | 不保存战斗内临时格挡 |
| `BattlePresenter` | 根据事件队列串联 Tween/VFX/SFX、更新 Control | 不决定战斗实际数值 |
| `ReplayLogger` | 记录 RNG seed、动作、战斗结果、分支选择 | 不靠 UI 截图当回放来源 |

**尽量采用纯逻辑 + 视图分离**：核心战斗状态用 `RefCounted` / 数据对象或资源承载，在无渲染环境可单独跑自动测试；展示场景只订阅状态/事件。Godot 的 `Control._gui_input()`、`mouse_filter` 与 `InputEvent` 可以支撑 GUI 与盘面输入分工，跨格拖动最好由一个统一 `PathController` 处理，避免每个按钮吞掉鼠标事件而断线。

### 8.3 数据文件建议

```text
res://data/
  glyph_pool.json        # 候选汉字及出场/奖励池
  word_lexicon.json      # 词自然性、长度、技能 ID、审核状态
  word_effects.json      # 行为/数值/条件/生效时机
  enemy_patterns.json    # 敌人意图、污染插入、护盾规则
  reward_pools.json      # 战后候选与权重
  shop_prices.json       # 商店基础规则
res://scripts/domain/      # 状态、牌袋、结算、词表逻辑
res://scenes/battle/       # 正式战斗屏
res://scenes/campaign/     # 奖励、商店、冒险地图
res://assets/reactions/    # 梗图，仅内部原型授权确认后再商用
res://tests/               # 逻辑测试、固定种子验证
```

**效果数据样例（示意，不代表每词最终数值）：**

```json
{
  "word": "回流",
  "recognized": true,
  "playable": true,
  "effect_id": "draw_random",
  "args": {"count": 4},
  "status": "trial"
}
```

带条件的词（如【反击】【合击】、热溢出、跨战永久能力）应由 `effect_id` 找到专门的规则类，并输出有序事件，不应试图用一个通用 `damage` 字段描述所有词。

### 8.4 预览与实际结算使用同一套规则

推荐流程：`路径变动 → validate_path → evaluate_preview(snapshot) → UI 更新`，释放时：`validate_path → commit_action → collect_events → 播放事件`。

预览是**只读计算**，不能提前消耗随机数、改变字袋或先拿走污染标签；涉及随机落点时显示“将随机抽 4 字，落点随机”，而不是假装知道未来究竟会抽到谁。要显示精确预期伤害则必须明确计算方法，防止“预览 12，实打 6”造成信任崩溃。

### 8.5 可复现性

- 一个战斗开始就固定 seed；抽牌、洗牌、敌方行动、商店奖励使用明确定义的 RNG 流。
- 保存玩家选择的格索引路径、每一条实际事件和关键状态；同 seed + 同操作应得到同结果。
- 弹梗图、粒子及动画不得消费战斗 RNG；视觉随机可使用单独 RNG。
- 强烈建议保留 CLI/无画面逻辑测试入口，以便将来使用 AI 对局反复测试构筑可行性。

## 9. 制作里程碑与可交付验收

### M0｜规则合同与输入原型（先做）

**交付：** Godot 新工程、4×4 棋盘场景、路径拖动控制器、离线词表、字袋/弃字堆、事件日志。

验收：无效多字路径不消耗；单字零效果可打出；空位不自动补满；可随时查到实体字在哪；回拖与鼠标松手行为正确。

### M1｜一场真正可玩的战斗

**交付：** 玩家/敌人 HP、攻击预告、临挡/持久盾、8～12 个简单词、敌方三类动作、实时预览、短梗图反馈、胜负界面。

验收：无需开发者改代码即可重新开局；完整经历多回合并可胜可败；表格与实战效果一致；PC 键鼠拖动可靠。

### M2｜空间机制与污染

**交付：** 【回】【回流】【重击】【重合】【加速】【冷却】等关键机制、敌方污染字、灼热字进入字袋、净化。

验收：重力计算仅按实际移动的实体字计数；重合不会吞/复制真实字；敌方污染字被消耗后不进入己方袋；过热垃圾字能在本场循环中持续出现。

### M3｜冒险循环纵向切片

**交付：** 3～5 场战斗、三选一奖励、金币商店、查看字袋、复制/删除/新字、跨战永久效果、存档与重试。

验收：同一初始牌组不同奖励会带来实际不同的后续字袋；胜负及商店开销可复现；战斗内临时格挡不跨战。

### M4｜内容与平衡

**交付：** 更多词效、敌人类型、词库发现、冒险深度、AI 试玩与可视化数值调试工具。

验收：测试报告覆盖组词率、无效拖动率、单字使用率、循环速度、不同构筑胜率、污染消耗率、长词启动率和极端经济循环。

**不列入第一版：** 完整 104 词、正式剧情、开放世界、美术世界观、联网 LLM、联网对战、复杂遗物联动、移动端适配。

## 10. 调试工具与测试案例（必须留预算）

**开发者功能建议：** 强制指定 16 格内容、指定抽字袋次序、强制创建 4 个同字、插入指定污染字、修改当前热度/热容、跳过敌人动作、查看每一笔字块去向、模拟战后奖励。否则像【重合】【合击】这种复杂系统会非常难排错。

| 测试 ID | 验收场景 | 期望结果 |
|---|---|---|
| T01 | 斜着连防→御 | 失败，不消耗 |
| T02 | 拖动防→御后回拖到防 | 路径缩成防，可按单字出 |
| T03 | 非词语两字路径松手 | 什么都不消耗，不扣行动机会 |
| T04 | 一个没有单字效果的普通己方字打出 | 字进弃字堆，未触发正面效果，触发短反应演出 |
| T05 | 污染【击】参与【反击】 | 反击效果与污染代价均结算；敌字消失 |
| T06 | 玩家自己过热溢出 2 | 本场字袋新增两枚带灼热标记的【热】 |
| T07 | 用【清洗】净化敌方字 | 原字、所有权不改变，污染标记被移除 |
| T08 | 回流消耗 2 字时盘面仅有 2 空位 | 最多补 4，但只能按实际空格/来源执行，不叠格 |
| T09 | 盘上 4 枚玩家【击】使用重合 | 保留一个原格，另外 3 实体回抽字袋，叠层总使用数 4 |
| T10 | 叠层未耗尽时执行【回】 | 不能在同格创建第二种实体字 |
| T11 | 【反击】在敌方多段攻击结束后触发 | 使用**剩余**临挡，不消耗持久盾 |
| T12 | 【连击】复制【放电】 | 进入“待定规则”测试，不得程序员默默选择第二次是否扣储能 |
| T13 | 战后删除一枚【击】 | 从唯一正确区域移除真实实体，后续抽取概率发生变化 |
| T14 | 相同 seed + 相同路径 + 相同奖励 | 得到一致的战斗事件与结局 |

**严禁用“总通关率好看”替代规则正确性测试。** 先保证玩家每一步都能理解，再做对战平衡。

## 11. 当前证据与主要风险

P25 Python 实验是**冒险循环的参考，不是 Godot 实现**。曾以 3 类启发式 AI × 3 种冒险模式 × 200 个初始种子，合计 **1,800 局**做比较；“三选一＋商店”的五战通关率在进攻 AI 与经济 AI 下均为 **15.5%**，而偏向多字组词的 AI 只有 **0.5%**。这说明奖励影响了结果，**不能证明多字词弱、某流派强或数值已经平衡**。基础敌人行为、奖励候选和 AI 策略都仍是简化版。P25 过热污染也几乎未被常规对局压力覆盖。

| 风险 | 影响 | 先采取的措施 |
|---|---|---|
| 组词概率太低 | 玩家常常只用单字，核心玩法流于点按钮 | 初始袋配比测试、放大空间操作奖励，记录词网连通度 |
| 补字太少 | 盘面卡住；补字太多又可无限循环 | 记录每回合有效行动、空格数与字袋循环情况 |
| 经济无限刷钱 | 商店永久成长失控 | 战内经济账本与压力测试，而非默认硬上限 |
| 高阶词几乎不能触发 | 【合击】【防御力】存在感弱 | 提供专门词组定向构筑奖励和手工测试盘面 |
| 污染无关痛痒 | 清洗等词成为纯对策陷阱 | 注入字不能无代价打出；统计污染实际伤害与阻塞成本 |
| 反应图片遮挡战斗 | 梗图从笑点变成干扰 | 面积小、0.4～0.7 秒、可关闭、连续触发合并 |
| 预览与实战不一致 | 玩家失去信任 | 同一结算器的只读预演与提交，两者事件核对 |

## 12. 尚待设计负责人明确的问题（带优先级）

**P0 · 写入正式结算前必须决定**

1. **合法中文词但无技能效果**是否允许作为“零效多字词”出掉？若允许，用梗图提示；若不允许，只对无效果单字提示梗图。两者均不得改变“非法多字路径不消耗”的底线。
2. 回合结束状态结算的统一时序：多段敌方攻击、【反击】、临时格挡清除、持久盾处理如何逐事件排序。
3. **重合**最后一层实体与临时层在多字路径、【回】换字、场景旋转和重力下的互动规格。
4. 污染代价结算顺序：是在词效前还是词效后？若污染字参与治疗词，治疗能否先救回扣血？
5. 新增灼热【热】能否跨战保留？首版建议“战内循环，战后清空”。

**P1 · M2 前确定**

6. 【连击】如何复制消耗储能/金币/热度的即时攻击，不能同时“只复制数值”和“复制词效”而无规则。
7. 【合击】激活时是否消耗【合】、是否留下【击】；延迟队列共享物理字时如何锁定与结算。
8. 热容降低引起的被动溢出是否生成污染；目前建议仅**主动升温超过上限**才发生溢出。
9. 是否给敌方攻击外的多种污染定制减伤规则；明确哪些属于直接生命损失。
10. 初始 16 枚字袋、12 枚落盘、每回合补 3 的最终配比，应由试玩重新检验。

**P2 · M3 之后逐步讨论**

## 13. 下一步开发执行顺序（给 Godot 项目的第一张任务单）

**第一个交付不是完整美术界面，而是一个完全遵守规则的可玩“白盒战斗”。**
